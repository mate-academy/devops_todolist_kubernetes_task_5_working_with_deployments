1. Попередні умови Для виконання цих інструкцій потрібен запущенний кластер Kubernetes з налаштованим доступом через kubectl. Необхідно встановити та запустити Metrics Server у кластері, оскільки він є обов'язковим для роботи HPA. 2. Створення Namespace Усі ресурси будуть ізольовані в окремому просторі імен mateapp. kubectl apply -f .infrastructure/namespace.yml 3. Розгортання застосунку (Deployment) Ми використовуємо клас якості обслуговування Guaranteed QoS (встановлюючи однакові requests і limits для CPU та Memory). Це забезпечує найвищий пріоритет для наших подів при плануванні та витісненні (eviction) ресурсів на нодах, гарантуючи їхню стабільну роботу. Обрана стратегія RollingUpdate з параметрами maxUnavailable: 1 та maxSurge: 1 дозволяє виконувати оновлення без простоїв (zero-downtime deployment). При 2 репліках це гарантує, що мінімум 1 старий под завжди працює, поки новий запускається. kubectl apply -f .infrastructure/deployment.yml 4. Налаштування автомасштабування (HPA) Horizontal Pod Autoscaler налаштований на діапазон від 2 до 5 подів. Тригери спрацьовують, коли середня утилізація CPU або Memory досягає 70% від заявлених requests. Ми використовуємо обидві метрики одночасно для проактивного масштабування (яке спрацює за метрикою, що першою перевищить поріг) перед тим, як навантаження вплине на продуктивність. kubectl apply -f .infrastructure/hpa.yml 5. Доступ до застосунку Для доступу застосовуються два сервіси: Внутрішній доступ (ClusterIP) kubectl apply -f .infrastructure/clusterip.yml Зовнішній доступ (NodePort) kubectl apply -f .infrastructure/nodeport.yml Як отримати зовнішній URL/Port: kubectl get services -n mateapp
