# ToDo список на Django

Це веб‑додаток «список справ» з базовими можливостями більшості веб‑застосунків: облікові записи/вхід, API та інтерактивний інтерфейс користувача. Для виконання цього завдання вам знадобиться:

- CSS | [Skeleton](http://getskeleton.com/)
- JS  | [jQuery](https://jquery.com/)

## Огляд

Спробуйте запустити, встановивши залежності (наступні команди працюють тільки з Python 3.8 і новіше через Django 4):

```
pip install -r requirements.txt
```

Створіть схему бази даних:

```
python manage.py migrate
```

Потім запустіть сервер (за замовчуванням http://localhost:8000):

```
python manage.py runserver
```

Тепер ви можете переглянути [API](http://localhost:8000/api/) або перейти на [головну сторінку](http://localhost:8000/).

## Завдання

Створіть Kubernetes-манифест для pod, який буде містити контейнер додатку ToDo:

1. Форкніть цей репозиторій.
1. Створіть файл `deployment.yml` з Deployment для додатку.
1. Deployment повинен мати
    1. Стратегію: RollingUpdate
    1. Запити та обмеження ресурсів (у стані простою має працювати 2 pod-и)
    1. Специфікація pod має бути такою ж, як у маніфесті pods
1. Створіть файл `hpa.yml` з Horizontal Pod Autoscaler для додатку.
1. Автоскейлер має визначати
    1. Мінімальну кількість pod: 2
    2. Максимальну кількість pod: 5
    3. Автоскейл має спрацьовувати за показниками CPU і пам'яті
1. Обидва нові маніфести повинні належати до namespace `mateapp`
1. Потрібно створити `INSTRUCTION.md` з інструкцією про те, як розгорнути додаток у k8s
1. `INSTRUCTION.md` повинна пояснювати ваш вибір запитів та обмежень ресурсів
1. `INSTRUCTION.md` повинна пояснювати ваш вибір конфігурації HPA
1. `INSTRUCTION.md` повинна пояснювати конфігурацію стратегії (чому саме такі числа)
1. `INSTRUCTION.md` повинна пояснювати, як отримати доступ до додатку після розгортання
1. Створіть PR з вашими змінами та прикріпіть його для валідації на платформі.
